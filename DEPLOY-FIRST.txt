SMART-CONTAINER CLOUD EDGE DEPLOYMENT

This folder is the GitHub-side collector. It does not run on the Linux server
and it does not depend on a local Windows computer.

Required deployment order:

1. Deploy the matching Linux backend folder first.
2. Apply Database/007_smart_container_multi_yard_import.sql to logistics_ai.
3. Generate one secret on Linux:

   openssl rand -hex 32

4. Configure these BaoTa backend environment variables and restart the API:

   KDocsCollector__Enabled=false
   SmartContainerImport__Enabled=true
   SmartContainerImport__ApiKey=THE_GENERATED_SECRET

   To enable the website manual collection button, also configure:

   GitHubActions__Enabled=true
   GitHubActions__Owner=T1mLuk0
   GitHubActions__Repository=chorme-channel
   GitHubActions__WorkflowFile=smart-container-edge.yml
   GitHubActions__Ref=main
   GitHubActions__Token=THE_GITHUB_TOKEN
   GitHubActions__MinimumIntervalSeconds=300

   The token is used only by the ASP.NET backend to call GitHub's
   workflow-dispatch API. Do not put it in frontend source or browser storage.
   It needs permission to dispatch workflows in this repository.

5. Create a private GitHub repository before uploading this folder.
6. In repository Settings > Secrets and variables > Actions, add:

   SMART_CONTAINER_IMPORT_URL
   https://eshinetong.com/api/smart-containers/import

   SMART_CONTAINER_IMPORT_SECRET
   THE_SAME_GENERATED_SECRET

7. Push the complete contents of this folder to main, including .github.

The first push starts one immediate Microsoft Edge collection. A validated
snapshot is posted directly to the backend and transactionally stored in
MySQL. Later scheduled runs execute every day at 01:10 UTC / 09:10 China time.
The ten-minute offset avoids GitHub's busy top-of-hour queue and gives the
external WPS editor time to finish its daily update. If the two worksheets
are being updated, each yard keeps its own source date. Different yards may
legitimately have different dates. A yard is rejected only when its own rows
do not resolve to exactly one source date. The backend applies the same rule.

The workflow uploads its JSON, raw TSV files, and WPS screenshot as a GitHub
Actions artifact for 14 days. Invalid or partial data is rejected before the
database transaction starts.

The website endpoint `POST /api/smart-containers/trigger?sourceKey=taicang`
starts the workflow with `dry_run=false`. It returns HTTP 202 after GitHub
accepts the dispatch request. The backend applies a five-minute default
cooldown to prevent repeated clicks from starting overlapping collections.
